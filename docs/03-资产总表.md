# 资产总表

> 唯一登记入口（开发纲领 §5）。新增 / 修改接口、表、页面、作业时必须同步更新本表，
> `scripts/ci_guard.py` 会静态校验代码与登记的一致性。
> 格式约定：接口行必须写成 `METHOD /path`（同一单元格），表名 / 作业名用反引号包裹，否则守卫无法识别。
>
> 限流档位（`app/limiter.py`，按用户维度：登录用户取 user_id，匿名取 IP）：
> `2/minute` 登录注册 · `6/minute` 外部连接测试（LLM/数据源，每次真实建连）·
> `10/minute` 重接口（SQL 生成/执行、向量索引、导出、上传、驱动安装、同步触发）·
> `30/minute` 写接口 · `120/minute` 读接口。`-` 表示不限流（仅静态页面）。

## 表清单

物理库（三库分离）：主库 `db/queryforge.db`（业务+元库），遥测库 `db/llm_telemetry.db`
（LLM 调用记录），日志库 `db/logs.db`（查询审计/同步历史等追加型高频写表）。

建表 SQL（集中管理，缺口8）：`deploy/schema_main.sql` / `deploy/schema_telemetry.sql` /
`deploy/schema_logs.sql`，由 `scripts/gen_schema_sql.py` 从 ORM 元数据自动生成，
CI 守卫检查项 6 校验漂移；存量 SQLite 库增量迁移清单见 `deploy/MIGRATIONS.md`。

## 红线与合规口径

- 禁止恢复纲领 §6.2 点名能力：collect / scan-doris / sync-doris / collect-stats / meta_collect / total_row / total_size_mb（`scripts/ci_guard.py` 静态守卫）。
- 同步合规口径：`schema_sync` 调度器只派发**用户在同步管理页登记的任务**（按数据源 + include/exclude 表 + interval），元数据读取走 information_schema 批量查询，不是系统级全量同步；新增同步能力必须维持"用户登记 + 任务级"边界，禁止平台自动遍历所有库所有表。
- 人工单表详情接口（纲领 §3.2）：当前未提供；如需新增（一次 SHOW CREATE TABLE），须行内标注 `# ci-guard: allow` 并登记本表，带限流/审计/短TTL缓存。
