# QueryForge 系统使用文档

> 版本：v1.5（2026-10） · 读者：业务用户、系统管理员
> 本文面向使用者。技术实现见《NL2SQL 设计与实现》，部署运维见《部署运维手册》。

---

## 1. 系统简介

QueryForge 是一个**用中文就能查数据库**的内部平台：

- 你不需要懂 SQL，用自然语言提问，系统自动生成 SQL 并执行，直接返回结果表格；
- 支持多轮对话："加上时间过滤""按大区分组""只要前 10 行"——在上一步结果上继续追问；
- 看不到的数据查不出来：每个人只能查自己有权限的库/表/字段，敏感字段只能用于条件不能出现在结果里；
- 管理员可以维护数据库结构、业务知识库、模型配置、用户权限，所有查询全程留痕。

## 2. 快速开始

### 2.1 登录

浏览器访问 `http://服务器地址:8888`，使用管理员分配的账号登录（默认端口 8888）。

- 登录状态通过 HttpOnly Cookie 保持，关闭浏览器后需重新登录；
- 忘记密码：联系管理员重置；登录后建议自行修改密码（右上角头像 → 修改密码）。

### 2.2 界面导览

| 区域 | 入口 | 说明 |
|---|---|---|
| 对话工作台 | 登录后首页 `/` | 核心功能区：新建对话、提问、看结果 |
| 知识库 | 首页左侧菜单 | 查看/维护业务口径知识（管理员维护，全员可用） |
| 管理后台 | `/admin` | 仅管理员：数据浏览、模型、同步、用户、权限、审计等 |

## 3. ChatSQL 对话查询（核心功能）

### 3.1 新建对话

1. 首页点击「新建对话」；
2. **不需要选择数据库**（全库模式）：系统按你的权限自动决定可查范围，跨库联合查询也能做；
   （部分部署也可指定单个库，按页面实际显示为准）
3. 输入问题，回车发送。

### 3.2 看懂返回结果

每次提问返回：

| 元素 | 说明 |
|---|---|
| 生成的 SQL | 点开可查看，可复制 |
| 结果表格 | 默认展示前 10 行，完整结果（上限 100 行）点「查看完整结果」 |
| Token 消耗 | 本次模型调用的用量 |
| 链路追踪 | 本次提问的完整处理过程（召回了哪些表/字段、权限判定、是否执行） |
| 提示补充信息 | 系统判断信息不足时给出缺失项和建议，补充后重问即可 |

### 3.3 多轮追问（推荐用法）

在同一个对话里连续追问，系统会记住上下文：

- "只看华东区的"
- "按月份分组"
- "把金额改成万元"
- "导出这个 SQL"（复制到本地执行）

**提问技巧**：

1. **一次问清一个主题**：时间范围、维度、指标、排序、条数说清楚，例如："查 2026 年 1-6 月各产品线的销售额，按销售额降序取前 10"；
2. **用业务术语没关系**：系统有知识库兜底，但表述越具体结果越准；
3. **维度层级**：涉及组织/科目等层级维度时，默认按最高级（根节点）统计，避免父子节点重复汇总导致数据翻倍；需要细粒度请明确说"按末级/明细"；
4. **结果不对先追问**：大部分偏差（条件、口径、时间范围）可以通过追问修正，不必重新开对话。

### 3.4 对话管理

- 左侧对话列表按更新时间倒序，支持分页/加载更多；
- 删除对话：列表右侧删除按钮（二次确认）；
- 对话中可随时切换模型/知识库（页面下拉选择，切换后本对话后续轮次沿用）。

## 4. 知识库

知识库用于把**业务口径、术语、计算规则、表关系**教给系统，生成 SQL 时自动注入。

| 类型 | 用途 | 示例 |
|---|---|---|
| note | 普通说明 | "销售额指不含税金额" |
| terminology | 术语别名 | "客单价 = 订单金额 / 订单数" |
| calculation | 计算规则 | "毛利率 = (收入-成本)/收入" |
| relation | 表关系（左右表+连接条件） | "订单表.用户ID = 用户表.ID" |
| value_domain | 取值域 | "订单状态：1=待支付 2=已支付" |
| convention | 约定规范 | "时间字段统一用 create_time" |
| entity_map | 实体映射 | "'华东区'对应 region_code in ('E1','E2')" |
| sample_qa | 示例问答 | 典型问题 + 正确 SQL 写法 |

使用建议：

- **别名（aliases）必填**：用户口语叫法（如"客单"）命中别名即召回；
- relation 类型填写两侧表与连接字段后，系统会在生成 SQL 时优先使用该连接条件，还会**自动把两侧表纳入上下文**（即使没被检索到）；
- 知识可设为全局或绑定到具体库（作用域）；
- 写口径时写"是什么、怎么算"，不要写大段背景介绍——注入 prompt 有长度成本。

## 5. 管理员功能

以下功能位于管理后台 `/admin`，仅管理员可见。

### 5.1 数据浏览与 Schema 管理

- **四级查看**：数据源 → 库 → 表 → 字段，支持按库名/表名/字段名/描述搜索；
- **CSV/JSON 导入**：下载中文表头模板（库名/表名/字段名/字段类型/…）填写后上传；也支持 Spider/自定义格式 JSON；
- **表关系维护**：人工登记表间 JOIN 条件（左表.字段 = 右表.字段），生成 SQL 时优先采用；
- **向量索引**：字段数 ≥ 50 的库自动构建；「向量索引」页可查看状态、手动重建（Schema 变更后如担心未生效，点一下重建）；
- **删除**：库/表/字段删除带二次确认；**删除由同步任务维护的库前，先停用对应同步任务**，否则 10 分钟内会被同步回来。

### 5.2 模型管理

- **模型配置**：支持任意 OpenAI 兼容 API——填供应商、模型名、API 地址、密钥即可（密钥加密存储）；可设默认、启停、公开共享（公开后普通用户无自有配置时可用）；
- **连通性测试**：保存前先测试，避免配错；
- **调用日志与用量**：查看每次调用的 prompt/响应、Token、成本、耗时；用量统计按 天×用户×模型 展示。

### 5.3 元数据同步（外部库表结构自动登记）

1. **数据源**：登记 MySQL/PostgreSQL/SQLite 连接（密码加密），可测试连接；
2. **同步任务**：选数据源 + include/exclude 表 + 执行间隔，登记后由调度器每 10 分钟巡检派发；
3. **变更审批**：源库新增表/字段自动应用；**删除类变更进审批流**（通过/拒绝），防止误删；
4. **执行历史与统计**：每次同步的结果、耗时、变更明细；
5. 「一键清空历史」可清理历史记录（保留策略：90 天自动清理）。

### 5.4 用户与权限

- **用户管理**：创建/编辑/启停/重置密码/删除用户（级联清理其授权、对话、模型配置）；保护规则：不能删/禁用自己，至少保留一名管理员；
- **角色权限**：角色绑定权限，按五层资源配置——数据源 → 库 → 表 → 字段 → 知识：
  - 字段三级：SELECT（可读可见）/ FILTER（只能用于条件过滤，不出现在结果里）/ NONE（不可用）；
  - 行级过滤：给角色配表级过滤表达式（如 `sales_region = '华东'`），该角色的查询自动注入 WHERE；
  - **数据源是总闸**：库/表授权不能脱离数据源生效；普通用户无任何授权 → 无可见数据；
  - 敏感字段默认规则：公开/内部 → SELECT，敏感 → FILTER，机密 → NONE（可在安全审计页调整字段敏感等级）；
- 改权限后 **5 秒内生效**（缓存 TTL），紧急情况无需重启。

### 5.5 安全审计

- **敏感字段分级**：公开/内部/敏感/机密四级，可批量调整；
- **审计日志**：每次查询记录问题、SQL、命中表/字段、是否拦截、耗时；
- **链路追踪**：每条审计可查看完整处理链路（召回→生成→网关判定→执行），排查"为什么被拦/为什么召回了这些表"看这个；
- 保留策略：审计日志 90 天自动清理。

### 5.6 其他管理功能

| 功能 | 说明 |
|---|---|
| 驱动管理 | 查看数据库驱动状态，缺失时一键 pip 安装 |
| 调度任务 | 查看 6 个内置作业状态，支持手动触发/暂停/恢复 |
| 系统设置 | JWT 有效期、注册开关（ALLOW_REGISTER，企业内部建议关闭）、向量参数（阈值/召回数/最大表数）、站点品牌（Logo、站点名） |
| API 文档 | `/docs`（Swagger UI）查看全部接口 |

## 6. 常见问题（FAQ）

**Q1：提问后提示"未配置 API 密钥"？**
没有可用的模型配置。让管理员在「模型管理」里配置（或公开一个公共模型），也可在对话中切换模型。

**Q2：提示"无权访问该数据库/字段"？**
你的角色没有对应授权。找管理员在「权限管理」中按数据源→库→表→字段开通；注意数据源授权是总闸。

**Q3：查询结果数字对不上？**
大概率是维度层级问题：维度表有父子节点时，不过滤会把父子一起汇总导致翻倍。追问时明确"按最高级统计"或指定具体层级；也可让管理员在知识库补口径。

**Q4：生成 SQL 报错（表/列不存在）？**
可能是召回不全。换更贴近业务术语的提问；或让管理员检查该库字段描述是否完善、向量索引是否需要重建。

**Q5：为什么查不到某张表？**
三种可能：没导入/同步该库；你的角色没授权；表在同步任务的 exclude 名单里。

**Q6：修改了表结构，查询还是用旧结构？**
字段变更会自动标记索引过期并后台重建；着急的话让管理员在「向量索引」页手动点重建。

**Q7：Token 消耗怎么统计的？**
每次 LLM 调用（含可行性判断）按 prompt/completion 计，遥测库留存 90 天，管理后台「用量统计」查看。

## 7. 最佳实践

| 角色 | 建议 |
|---|---|
| 业务用户 | 提问写清四要素：时间范围 + 维度 + 指标 + 排序/条数；结果先看链路追踪再追问；高频口径让管理员沉淀进知识库 |
| 管理员 | ① 导入 Schema 后补全字段中文描述（召回质量的主要来源）；② 表关系全部人工登记，杜绝模型猜连接字段；③ 权限按"数据源→库→表"逐层授，字段级默认推导即可，特殊字段再单授；④ 公共模型公开给全员，减少个人配置；⑤ 每周看一次审计日志的拦截记录 |
