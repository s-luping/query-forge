# QueryForge 系统架构设计

> 版本：v1.5（2026-10） · 读者：开发、运维、架构评审
> 配套文档：《系统使用文档》《NL2SQL 设计与实现》《部署运维手册》《开发纲领》《资产总表》

---

## 1. 系统定位

QueryForge 是公司内部的**自然语言数据查询平台（NL2SQL）**：用户用中文提问，系统基于已登记的数据库结构（Schema）检索字段，调用大模型生成 SQL，经权限网关校验后自动执行并返回结果。

核心价值：

- **零 SQL 门槛**：业务人员用自然语言即可查数，多轮对话迭代修正；
- **数据不出内网**：Schema 元数据与查询结果仅经内网流转，大模型 API 地址受 SSRF 防护约束；
- **权限内建**：四层权限（数据源→库→表→字段）+ 行级过滤在 SQL 生成与执行双环节强制生效，越权查询在网关层拦截并留痕。

## 3. 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| Web 框架 | FastAPI + uvicorn | 单进程部署（workers=1），DEBUG 模式可开 reload |
| ORM | SQLAlchemy 2.0 | 双/三基类：MainBase / TelemetryBase / LogsBase |
| 数据库 | SQLite（WAL，默认）/ MySQL / PostgreSQL | `app/settings.py` 改 `DATABASE_URL` 即切换 |
| 大模型 | 任意 OpenAI 兼容 API | 通用客户端，供应商/模型/地址前端自由配置 |
| 向量模型 | sentence-transformers + BGE-M3 | 1024 维，本地推理，ModelScope 下载 |
| 向量索引 | 纯 NumPy（无 FAISS） | pickle 持久化，降低部署复杂度 |
| SQL 解析 | sqlglot | 权限网关 AST 解析、跨库表名提取 |
| 中文分词 | jieba | 关键词提取 |
| 调度 | APScheduler（AsyncIOScheduler） | 6 个内置作业，Asia/Shanghai 时区 |
| 限流 | slowapi | 按用户维度分档限流 |
| 前端 | HTML + JS + Bootstrap 5 | 无构建步骤，改完即生效 |
| 加密 | bcrypt（密码）/ Fernet（密钥、数据源密码） | 密钥派生自 SECRET_KEY |

## 5. 数据库架构（三库分离）

按**写入特征**物理分库：交互域短事务、追加型高频写、审计历史分别落库，避免相互拖累。

| 库 | 文件 | 内容 | 表 | 外键 | WAL |
|---|---|---|---|---|---|
| 主库 | `db/queryforge.db` | 业务 + 元数据 | users / roles / user_roles / role_permissions / db_schemas / db_tables / db_columns / db_table_relations / data_sources / knowledge_items / conversations / conversation_messages / llm_configs / llm_usage_stats / system_settings / vector_index_meta / sync_job_configs（17 张） | 开启 | 开启 |
| 遥测库 | `db/llm_telemetry.db` | LLM 调用明细（高频追加写） | llm_calls / llm_prompts（2 张） | 关闭 | 开启 |
| 日志库 | `db/logs.db` | 查询审计 + 同步历史（高频追加写） | query_audit_logs / sync_run_logs / schema_change_logs（3 张） | 关闭（跨库引用降级为索引列，应用层级联清理） | 开启 |

要点：

- SQLite 三库均启用 `WAL + busy_timeout=5000 + synchronous=NORMAL`；遥测/日志库不开外键（跨库引用由应用层保证）。
- 切外部数据库（MySQL/PG）时遥测/日志库默认与主库同址，通过 ORM Base 类隔离表；也可填独立连接串。
- 连接池：QueuePool，主库 pool_size=10 / max_overflow=20 / recycle=3600；外部数据源查询引擎 pool_size=1 / max_overflow=2 + pre_ping。
- 建表以 ORM `create_all` 为准；`deploy/*.sql` 由 `scripts/gen_schema_sql.py` 从 ORM 生成，CI 校验防漂移；存量 SQLite 库靠 `db/sqlite_hooks.py` 幂等增量迁移（清单见 `deploy/MIGRATIONS.md`）。
- **数据保留策略**（scheduler 每日执行）：遥测 90 天（03:00）、审计/同步历史 90 天（03:10）、对话结果 JSON 30 天（03:30）、WAL checkpoint（04:00）。

### 5.1 四层元数据模型

```
数据源 data_sources（外部库连接，密码 Fernet 加密）
  └── 库 db_schemas（datasource_id 可空：手动导入的库归入「未关联数据源」）
        └── 表 db_tables
              └── 字段 db_columns（类型/注释/键/外键/示例值/敏感等级/维度度量标记）
```

- 表关系 `db_table_relations`：left/right 各自带 schema_id，支持同数据源跨库 JOIN。
- 向量索引元数据 `vector_index_meta`：状态（pending/building/ready/stale/error）、字段数、表数、维度、pickle 路径。

## 6. 认证与权限体系

### 6.1 认证（JWT）

- 登录成功签发 JWT（HS256），**HttpOnly Cookie** 下发（前端 JS 不可读，防 XSS 窃取），同时支持 `Authorization: Bearer` 头双通道；
- 令牌携带 `pwd_ts`（密码变更时间戳）：改密/重置密码后旧 token 立即失效；
- 有效期 `ACCESS_TOKEN_EXPIRE_MINUTES`（默认 4320 分钟 = 3 天），系统设置可改；
- 签名密钥从 `system_settings` 表或 `config.SECRET_KEY` 读取，两处都缺**拒绝启动**（无硬编码兜底）；
- 未登录访问页面 302 跳 `/login`；管理模板（system/、llm_config、vector_index）与 `/docs` 非管理员 403；
- 登录/注册限流 2/minute，恒定时间校验防用户名枚举计时差异。

### 6.2 权限模型（角色化 RBAC，四层）

```
users → user_roles → roles → role_permissions
resource_type: route / page / schema / table / column / datasource / knowledge / row / metric
access_type:   ALLOW / SELECT / FILTER / NONE / DENY
```

| 层 | 语义 |
|---|---|
| 数据源 | 可见性**总闸**：库/表授权不能脱离数据源生效 |
| 库（schema） | `resource_id=None` 表示全量授权；DENY 强制剔除 |
| 表 | 同库内配置了任一表授权 → 仅名单内可见；仅 DENY → 全表减被拒表 |
| 字段 | SELECT（可读可见）/ FILTER（可用不可见）/ NONE（不可用） |

- 默认推导（无显式角色授权时按敏感等级）：公开/内部 → SELECT，敏感 → FILTER，机密 → NONE；
- **行级过滤**：`row` 类型授权携带 `filter_expression`，网关自动注入 WHERE（如"销售只能看自己大区"）；
- 层级门控：管理员也不再整体绕过——角色配了 DENY 同样生效，仅"无任何授权"时保留超管全可见；
- 权限三件套（visible_schema_ids / table_grants / column_access_map）有 **5s TTL 进程级缓存**，单次 chat 请求内复用；权限变更时 `invalidate_permission_cache()` 立即失效。

## 7. NL2SQL 核心链路（概要）

详细设计见《NL2SQL 设计与实现》，此处仅列架构位置：

```
用户问题
 → ① 入口校验（鉴权 + 库可见性 + 模型配置 + 知识加载）   conversation_router
 → ② 关键词提取（jieba）                                core/ret_keywords.py
 → ③ 字段召回（BGE-M3 向量 top-K + DB 关键词并集兜底，
     权限掩码剔除不可见字段）                            core/ret_retriever.py
 → ④ 按表聚合（MAX_TABLES 裁剪 + 权重保留向量命中表）      core/ret_retriever.py
 → ⑤ 知识召回（typed 知识关键词命中；relation 知识跨库扩表）core/ret_retriever.py
 → ⑥ 可行性判断（信息不足 → 返回 missing_info 不生成）      core/gen_sql.py
 → ⑦ LLM 生成 SQL（system prompt = 表结构CSV + 规则 + 领域知识 + JOIN 提示）
 → ⑧ SQL 校验（仅 SELECT/WITH、禁写关键字、禁注释符）      core/gen_sql.py
 → ⑨ 权限网关（AST 解析 → 表/字段校验 → 禁 SELECT* → 行级注入）services/sql_gateway.py
 → ⑩ 执行（只读，按库前缀路由数据源，引擎缓存复用）          services/sql_executor.py
 → ⑪ 落库（对话/消息 + 遥测 llm_calls + 审计 pipeline_log）
```

## 8. 向量检索子系统

| 组件 | 文件 | 职责 |
|---|---|---|
| `EmbeddingModel` | `core/ret_vector_store.py` | BGE-M3 封装，单例加载；路径从 `system_settings` 缓存，失效则扫描 `models/embeddings/` 补齐 |
| `SchemaVectorStore` | 同上 | 纯 NumPy 索引：L2 归一化内积检索、pickle 持久化（`db/vectors/`）、权限掩码搜索 |
| `mark_index_stale` | `services/vector_service.py` | 导入/同步后仅标记索引过期，**不再自动构建**；重建统一由定时任务「向量索引重建」（`scheduler/jobs/vector_index.py`）执行，仅 stale/error/缺失 时构建（幂等），构建期间旧索引原子保留继续服务 |

**三级降级链**：DB 元数据 ready → 磁盘 pickle → 数据库 LIKE 关键词查询；任何一级失败不阻断生成流程。索引为**全库统一索引**（无库前缀），召回时用权限掩码保证 top-K 名额不被不可见字段挤占；向量结果再与 DB 关键词召回做并集，覆盖未建索引的库。

## 9. 元数据同步子系统

```
数据源（MySQL/PG/SQLite，密码加密）→ 同步任务 sync_job_configs（用户登记：include/exclude 表 + interval）
   → scheduler 每 10 分钟巡检派发到期任务（run_scheduled_syncs）
   → sync_connectors 读源库 information_schema（批量查询，禁止逐表循环）
   → sync_diff 比对 → 新增自动应用 / 删除变更进审批流（schema_change_logs）
   → sync_run_logs 记录每次执行
```

合规边界（开发纲领 §6）：只派发**用户在同步管理页登记的任务**，不提供系统级全量同步；删除由同步维护的库前须先停用对应同步任务（否则调度器会把它同步回来）。

## 11. 安全体系

| 面 | 措施 |
|---|---|
| 密码 | bcrypt（rounds=12）哈希；历史明文登录成功后自动升级 |
| 密钥 | JWT 签名密钥缺配拒绝启动；Fernet 密钥从 SECRET_KEY 派生 |
| 敏感配置 | LLM API Key、数据源密码 Fernet 加密存储，接口不回显 |
| SQL 执行 | 只读：仅 SELECT/WITH；写关键字拒绝；注释符视为注入 |
| 权限网关 | AST 级表/字段校验、禁 `SELECT *`、行级 WHERE 注入、敏感命中留痕 |
| SSRF | LLM API 地址仅 http/https，禁止内网 IP（10/172.16/192.168/127/169.254 等） |
| 响应头 | CSP（frame-ancestors 可配）/ X-Content-Type-Options / Referrer-Policy / HTML 禁缓存 |
| 审计 | 查询全链路（query_audit_logs.pipeline_log）、写操作与权限变更（audit.log）、LLM 调用（遥测库）、页面访问（server.log）四路留痕 |
| 限流 | slowapi 分档：登录注册 2/min、连接测试 6/min、重接口（生成/执行/索引/导出/上传）10/min、写 30/min、读 120/min |

## 12. 可观测性

- **四类日志**（`logs/`，均自动轮转）：`app.log`（业务，10MB×5）、`llm.log`（模型调用详情，10MB×5）、`audit.log`（审计，10MB×5）、`server.log`（uvicorn 访问，按天×30）；
- **traceId**：每次请求生成，贯穿访问日志、慢 SQL 日志、错误响应体与 `X-Request-ID` 响应头；
- **慢查询观测**：接口 > `SLOW_REQUEST_MS`（1000ms）记 `[SLOW]` WARNING，SQL > `SLOW_SQL_MS`（500ms）记 `[SLOW SQL]` WARNING（只记语句文本不记参数，防敏感值入日志）；
- **链路追踪**：NL2SQL 全流程每步写入 `query_audit_logs.pipeline_log`，前端审计页「链路追踪」弹窗展示（召回字段、权限统计、网关判定、执行结果）。

## 13. 设计原则与红线

遵循《开发纲领》，架构层面固化的原则：

1. **高内聚低耦合**：模块只做一类事，模块间走接口/服务层，公共能力（连接器、sql_guard、审计、鉴权、响应结构）下沉共享层；
2. **查询合并**：同请求同源查询合并，元数据一次 `IN (...)` 左联，禁止逐表循环查 information_schema；
3. **性能预算**：列表 O(1)~O(库数)、详情 O(1)、批量 O(批次数)，不随表数线性增长；接口 P95 与 SQL 条数写入设计预算；
4. **资产清单化**：接口/表/页面/作业/指标/字典/审计事件统一登记于 `docs/03-资产总表.md`，`scripts/ci_guard.py` 静态核对，新增路由未登记即 CI 失败；
5. **红线（禁止恢复）**：系统级全量同步、循环 SHOW CREATE TABLE、逐表统计、跨表汇总行数/空间（total_row / total_size_mb）、collect / scan-doris / sync-doris 系列能力；
6. **Git 纪律**：一个 commit = 一个可独立回滚的逻辑单元，多主题必拆分，提交信息与 diff 一致。
