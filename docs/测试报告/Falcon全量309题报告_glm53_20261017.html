五、关键结论

  • 比对口径影响巨大：按「忽略列名/行序（要求排序除外）」的分层比对（多重集 → 忽略大小写 → 列排列/多余列剔除）， 列排列层单独挽回 52 题——旧口径下这些题因输出列多/列序不同被误判。评测 NL2SQL 必须先把形态噪声从语义错误中剥离。
  • col_mismatch 是最大桶但非纯形态问题：74 题中仅 4 题是纯形态（列裁剪后即正确），60 题在列数不符的同时 值也不对（多余列 + 数值口径/清洗错误复合）——「结果形态」约束仍需强化，但单靠形态规则救不了这个桶。
  • 枚举值幻觉是空结果的第一根因：大量 empty_result 案例把枚举值写成中文或自造值 （如 Customer_Segment='钻石' 实际是 'Diamond'、shipment_status='已送达' 实际是 'Delivered'）。 解决路径优先级：元数据同步时对低基数字段自动采样 DISTINCT 值注入召回 > 知识库枚举清单 > prompt 常驻提醒。
  • 数据清洗陷阱独立成类：'$' 前缀、千分位逗号、'+' 后缀（installs）、字符串数字必须 CAST 清洗， gold SQL 全部显式处理而生成 SQL 常漏——清洗片段模板直接进知识库 L3 层可复用。
  • 口径歧义集中在"隐含分母/隐含字段选择"：占比类题的分母（全部 vs 筛选后）、 "评分"字段选择（行程评分 vs 司机档案评分）、"每位"是否含 0 计数行（LEFT JOIN 保底）， 是 disjoint/value 类失败的主因——正是 L1/L2 业务口径知识层的目标场景。
  • 拦截质量良好：26 题拦截多为真歧义（枚举值/计算口径缺失），拦截原因从"缺表"已质变为语义歧义， 说明召回链路问题基本清除，剩余是知识问题。

L1 业务术语黑话/同义词 → 标准字段（如"评分"=司机档案 average_rating 而非 rides.Rating） term, synonyms[], mapping(table.column), definition常驻（精简表）+ 向量召回disjoint / value_diff
L2 字段口径字段计算口径、单位、枚举值含义、分母定义（如"占比"分母=全表而非筛选后） table.column, caliber(口径描述), formula, enum_meanings{}按召回字段注入（跟随 TopK）value_diff / partial_overlap
L3 数据质量格式陷阱：$ 前缀、TRIM、字符串数字、空串、日期格式、NULL 语义 table.column, pitfall(陷阱), cleaning_hint(SQL 片段模板)常驻（按库汇总成一段）empty_result / disjoint
L4 关联链路join path：表A↔表B 经由哪个字段、桥表、1:N 语义、易漏中间表 tables[], path(A.col→B.col), relation(1:1/1:N/M:N), remark向量召回（查询涉及相关表时注入）fewer_rows / partial_overlap / 拦截
L5 输出规范结果形态约束：单值列、GROUP BY 触发词、排序 tie-breaking、百分比 vs 小数、列数 rule, scope(global/schema), example常驻（已在【结果形态】段落地，持续补规则）col_mismatch / order_mismatch

2. 落地路径（利用现有设施）

  • 存储：新表 kb_entries（schema_name, category L1-L6, title, content, applies_to(JSON: 表/列), embedding(vector), source(manual/error_case), enabled）；复用现有向量索引管线， kb_entries 单独建索引，与字段召回并列成为第三路召回源。
  • 注入：L3/L5 常驻进生成 prompt（按库拼段，控制 token 上限）；L1/L2/L4 与字段召回同路检索， 命中的字段携带其口径与关联条目；L6 检索相似历史问题注入 few-shot。
  • 入口：数据指南编辑弹窗升级为知识库管理页（分类标签 + 生效范围 + 启停）； 错题归因页面（本报告的逐题明细）可一键"转知识条目"，人工修正后入 L6。
  • 运营闭环：每次基准回归 → 自动归因分桶 → 高频桶人工审核 → 沉淀知识条目 → 回归验证 EX 提升， 形成"评测-归因-沉淀-复测"循环。

3. 知识库之外的提准手段（按性价比排序）

  • 执行反馈自修复（预计收益最大）：空结果/执行报错时，把"0 行"与 SQL 反馈给 LLM 重生成一次 （限 1 次，控成本）——直接命中 empty_result 桶与 exec_error。
  • 多值列截断器：生成后静态校验 SELECT 列数/多余列（对照问题意图），命中 L5 规则自动裁剪—— 针对 col_mismatch 中"多输出列"形态。
  • 有序题 tie-breaking 规范：问题含"排名/前十/最高"时，prompt 强制 ORDER BY 显式含次级排序列； is_order 题 gold 无法穷举，只能减少随机性。
  • 召回链路补全：小库直通已解决 20 表以下场景；大库（falcon_dev_14 等）继续调 FIELD_RECALL_TOP_K 并把 L4 关联链路知识作为召回加权依据。
  • 数据清洗片段库：L3 沉淀的 cleaning_hint 直接可被生成 prompt 引用为 SQL 模板 （如 CAST(REPLACE(TRIM(col),'$','') AS DECIMAL)）。
