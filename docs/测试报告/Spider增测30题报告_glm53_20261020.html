五、重要发现：元数据同步产品 bug（已修复）

现象：spider_dog_kennels 元数据同步始终失败（UNIQUE constraint failed: db_columns.table_id, db_columns.name），导致该库 0 表元数据、q922 被"信息不足"拦截 （拦截本身正确——召回确实无表可用）。

根因两层：① Spider 的 dog_kennels SQLite 源对 dogs.owner_id 重复声明了两次相同外键， 本项目的导入脚本照单全收建了两个重复外键约束；② QueryForge sync_connectors.py MySQL 连接器的元数据查询用 KEY_COLUMN_USAGE LEFT JOIN 取外键， 一列参与多条外键时行翻倍，同一列被插入两次撞 UNIQUE 约束——任何源库存在"一列多外键/重复外键"都会同步崩溃。

修复：① services/sync_connectors.py：按 (表,列) 去重，多外键引用合并为一格 （ref1 | ref2）——产品级修复，惠及所有 MySQL 数据源；② benchmark/spider_bench.py： 导入时按 (引用表,本地列,引用列) 去重外键；重建 dog_kennels 后同步 8/8 成功，q922 复测通过。 建议纳入同步链路回归测试（一列多外键用例）。

六、失败归因（增测 4 题）

① spider_dev_460（形态类·列序，宽口径可通过）——模型输出 (Julia, USA) 与 gold 完全同值， 仅列序不同；Spider gold 的 SELECT 列序与题面用词顺序不一致（题面 first name 在前，gold country_code 在前）。 与 Falcon 收敛期「ID vs name」同类：形态不可判定题。

② spider_dev_311 / ③ spider_dev_421（并列最值 tie，宽口径部分可判）—— 模型用 DENSE_RANK 保留并列全部结果（3 行 / 2 行），gold 用 LIMIT 1 在并列中任意取一行； 模型结果严格包含 gold 结果。与 Falcon q218、BIRD tie-breaking 同族， 业界通行做法是按并列分桶或保序比对。

④ spider_dev_469（gold 口径 quirk，不可两全）——「average ranking for each player」： gold 按 GROUP BY first_name 聚合（同名球员合并成 1580 组）， 模型按 player_id 分组（2000 组，语义更符合「each player」）。 按题意模型是对的，gold 自身口径存疑——归入「gold 口径差」不再耗优化预算。

七、口径说明

  • 比对：多重集合比较（行序无关），NULL→"NULL"、float 4 位小数、字符串去空格；gold 与生成 SQL 均落 MySQL 执行。
  • 失败题处理：异常题（q1031 首跑 500）与拦截题（q922 修复后）自动/手动重试，以最终结果计。
  • Token：遥测 llm_calls usage 回传，增测 30 题 Σ入 63,227 / Σ出 12,940（含 reasoning 11,375）。
  • 耗时：最长 107.9s（car_1 分组题），无 504/超时失败；NVIDIA 本轮稳定性好于首轮。
