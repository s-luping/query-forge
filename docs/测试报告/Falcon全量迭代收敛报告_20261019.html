二、本轮（第 6 循环）三项系统级修复

  • MySQL 8.0.12 方言陷阱（一次性 9 题 exec_error）：子代理重放实证 CAST(x AS DOUBLE) 为 8.0.17+ 语法、窗口 ORDER BY 引用同层 SELECT 别名需 8.0.14+——此前我们自己注入的「AVG(CAST(col AS DOUBLE))」规则正是 9 题报错根因。已改写全局规则与「MySQL 8 语法陷阱」条目（DECIMAL(18,4) 替代、别名禁用、单条 SELECT），验证批 qid30 恢复可执行。
  • 「点明玩具限 Toys」条目纠偏（3 题）：qid19/23/293 重放证实 gold 对单一「玩具」量值/占比/明细题不过滤品类（仅 qid20 的 gold 过滤，gold 自身不一致）。条目改为仅品类对比维度时过滤，验证批 3/3 翻正。
  • 「ID 优先」条目与 gold 系统性冲突（10+ 题证据）：dev_26 六题 gold 要球队/球员名称，dev_14 四题要店名。全局规则 1 改为「标识列形态跟随题面用词」，验证批 qid20 翻正（qid141 因 gold 自身 ID/name 混用仍错，归类 gold 不一致）。
  • 附带产品 bug：main.py _validation_handler 把 pydantic ctx 中的 ValueError 对象直接 json 序列化导致二次 500——已修复（ctx 展平为字符串）。

三、本轮知识库与数据指南沉淀（kb_seed.py 最终版）

全局常驻 4 条（人人注入）

  • 输出规范：最小列集（标识列跟随题面用词、"XX信息"输出全字段、排名列置尾）；占比不乘100；聚合默认 INNER JOIN（仅计数补零类 LEFT JOIN）；并列口径三分法（Top-1 极值 DENSE_RANK 全并列 / 榜单 RANK 并列 rank<=N / 组内逐行排名 ROW_NUMBER）；不硬编码枚举；AVG 用 DECIMAL(18,4)。

  • 新增加州归属/折扣限定（dev_20）、店铺级+库存孤儿键（dev_14）、RANK 并列+35.6 万行大表先聚合（dev_26）、订单行级+全字段输出（dev_21）、金额字段分场景（dev_28）、Card_Family 映射（dev_15）、重复行/NULL/区间格式（dev_8）、销售额单位百万（dev_7）等。

五、关键教训（方法论沉淀）

  • 测量先行：两处比对器缺陷合计影响 60+ 题判定——优化前先确保测量口径正确，否则归因方向会被系统性误导。
  • KB 双刃剑，实证才能上架：三条规则（ID 优先、玩具限 Toys、COLLATE 强制）各有 3~10 题反证，全部靠 MySQL 重放实证后修订/撤销；「规则写反比不写更糟」三次实证。
  • 影响召回的状态迁移必须查 prompt 验证：KB 可见性迁移导致枚举段全线失注，页面看不出、只有 llm_prompts 遥测能实锤。
  • 执行环境方言要写进常驻规则：MySQL 8.0.12 的 CAST AS DOUBLE/窗口别名限制是评测环境特有，模型无从得知，必须显式注入。
  • gold 不一致是基准固有噪声：占比乘不乘 100、并列取不取、ID 还是 name，gold 内部均存在双口径——继续优化应转向「执行反馈自修复」「多答案容差」，对 gold_quirk 建议上游修订标准答案。
  • 小批验证循环（≤10 题）足以验证修复方向且省 20 倍成本；全量重跑只在测量口径变化时执行。
