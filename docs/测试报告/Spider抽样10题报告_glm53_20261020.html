二、数据集接入

  • 数据源：Spider 1.0 官方包（spider.zip 99.7MB + dev.json + dev_gold.sql + tables.json）， ModelScope ModelM/spider 国内直连约 1 分钟；GitHub/HF 官方渠道均不可直连或缺库文件。
  • 导入：10 个 dev 库 → 本地 MySQL spider_<db_id> （concert_singer / pets_1 / car_1 / flight_2 / employee_hire_evaluation / cre_doc_template_mgt / course_teach / museum_visit / wta_1 / battle_death，最大 wta_1 rankings 51 万行）。
  • 导入修复的 3 个坑（脚本 benchmark/spider_bench.py，可复用于全量接入）： ① SQLite 无类型声明列做主/外键时 TEXT 不可索引 → 键列映射 VARCHAR(255)； ② Spider gold schema 外键两端类型常不一致（如 concert.Stadium_ID text 引用 int 列）→ 本地列类型跟随被引用列； ③ 被引用的非主键列（model_list.Model）MySQL 建外键时必须已有索引 → 建表 DDL 内联建索引； 另：BIGINT 列的空串脏值（wta_1 rankings.player_id=''）批量转 NULL。
  • QueryForge 接入：10 个数据源（id 24~33）+ 全量同步任务 + 向量索引重建 （721 → 909 字段，BGE-M3，全部 success）。
  • 抽题规则（固定可复现）：按 dev.json 库首现顺序逐库取第一条 gold SQL 可在 MySQL 执行的题， 优先选含 JOIN 的题（鉴别召回/关联能力），无 JOIN 可执行题时回退第一条；每库 1 题，共 10 题。 gold 结果集在导入库上离线执行落标。

四、失败归因

① spider_dev_496（形态类，宽口径可通过）——问句「What are the death and injury situations…」， gold 只取 killed, injured 两列，模型多加了 note 列。剔除 note 后 11 行与 gold 完全一致。 与 Falcon 收敛期结论同源：【结果形态】约束只要求"不加题目未要求列"，但英文 question 的 "situations" 语义边界模糊，模型倾向补充上下文列。

② spider_dev_459（口径类，不可两全）——「did the most number of tours」： gold 直接 JOIN rankings ORDER BY tours DESC LIMIT 1（按单行 tours 最大值所在的行取玩家， SQLite 弱语义，未聚合也未去重）；模型按 SUM(tours) 逐玩家聚合后取第一， 两者胜者不同（gold: USA/Julia，gen: GRE/Eleni）。该题与 Falcon q218 / BIRD tie-breaking 同属 "gold 依赖未声明语义"类。另：首跑 NVIDIA glm-5.3-flash 对该题思考 300s 超时 504（重试 130s 完成）， 与既有记录「NVIDIA 对含糊题易思考到读超时」一致。

五、评测口径说明

  • 比对：多重集合比较（行序无关），单元格归一化 NULL→"NULL"、float 保留 4 位小数、字符串去首尾空格；gold 与生成 SQL 均落 MySQL 执行。
  • 宽口径：沿用 Falcon 收敛版比对器的「多余列剔除」层（生成结果列数 = gold+1 时尝试剔除后比对）， 本轮仅 spider_dev_496 受该层影响。
  • 链路：POST /api/conversation（schema_name=spider_<db_id> 绑定库模式，小库直通召回）， llm_config_id=7，客户端超时 600s；异常题自动重试（q459 首跑 504 已重试）。
  • 行数上限：SQL_MAX_ROWS=2000，本轮 gold 结果集最大 11 行，未触及。
  • Token 统计取遥测 llm_calls 回传 usage：Σ入 21363 / Σ出 5586（出含 reasoning）。

六、结论与下一步

  • 接入结论：Spider 1.0 dev 接入成本低于预期——20 库全为小库，gold SQL 在 MySQL 的可执行率高 （抽题过程中仅 wta_1 两题因 SQLite 专有语法不兼容被跳过），导入坑集中在类型映射，已沉淀为可复用脚本。
  • 链路结论：小批 10 题未暴露召回/网关/拦截问题；英文元数据 + 英文提问链路顺畅（与 northwind/sakila、Falcon 结论一致）。
