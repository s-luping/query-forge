一、系统级发现：KB 条目可见性迁移击穿评测召回（最重要）

批测中 qid113/191 仍写 'Cancelled'/'已发货'（实际值 Canceled/Shipped），但 dev_21 枚举条目早已播种。查遥测库 llm_prompts 实锤：10-17 的 prompt 含「电商订单枚举值」段，10-18 的 prompt 全部缺失。

根因：10-18「条目归属重划」把 kb_seed 播种的 15 条枚举/口径条目（id 17-31）迁移为 visibility='personal'（属主 kun）——而评测以 admin 跑，召回可见性过滤（global 人人可见 / personal 仅属主+授权）把这些条目全部挡掉，所有用户（含 admin）的枚举段自此失注。

修复：15 条恢复 visibility='global'（属主保留 kun，global 条目本就不进对话勾选下拉，不违背 UI 决策）；kb_seed.py 增加可见性自愈——播种时发现既有条目 visibility≠global 即原地 PUT 恢复，防止再次被迁移击穿。

影响面：该 bug 使 10-18 之后所有评测/对话的 12 库枚举值注入失效——此修复对全量 EX 的收益有待下次全量复测量化。

二、比对器扩展：仅多 1 列的排列穷举

qid191 型错（明细题多输出一列状态列，8 列 vs 7 列）原被 P(8,7)=40320 超过 5040 上限直接放弃。run_eval.py 新增例外：pcols=gcols+1 且 gcols≤7 且行数≤100 时排列上限放宽到 40320。（qid191 最终仍错——真因是标注文案 gold '是大额订单' vs pred '是'，标注字符串不可推断，属 gold quirk。）

三、KB 口径条目迭代（本轮新增 3 条）

  • dev_14「玩具店口径补充」：①点名"玩具"且非类别级题限 Product_Category='Toys'（qid20 gold 口径）；②「每个城市的店铺」按店铺级分组不合并城市（qid134）；③「排名前 N 且 <X」先过滤后排名；④金额/利润类 INNER JOIN 不补零行（仅计数类补零，qid134）。
  • dev_21「电商订单口径」：①"总数量为4件/总金额超200"按订单行级判定再取客户 DISTINCT，不按客户预聚合（qid42）；②枚举值逐字符照抄（Canceled≠Cancelled、Shipped≠已发货、Tools≠工具箱）。

五、结论与建议

  • 归因格局变化：KB 生效后，dev_14/21 的 $ 清洗类、枚举类、形态类错误大部分消失；剩余失败向「gold 口径/形态不可判定」集中（id vs name、标注文案、题面与 gold 语义相反），此类建议在全量报告中单独统计为「gold 口径差」，不再消耗优化预算。
  • 可见性 bug 的教训：知识条目的可见性语义（global=召回可见）与 UI 归属管理（条目迁 personal）耦合——凡影响召回的状态迁移必须跑一次"prompt 注入验证"（查 llm_prompts 是否含关键段）而非只看页面。
  • 建议下一步：① 可见性修复惠及 12 库枚举注入，值得安排一次全量 309 复测量化真实 EX（预计明显高于 46.6%）；② 若暂不跑全量，可对 dev_20（17 失败）/dev_28（6 ER）/dev_15（8 失败）继续小批同法迭代；③ 比对器已含 r2 + 多 1 列扩展层，新跑批自动生效。
