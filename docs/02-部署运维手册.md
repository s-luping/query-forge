# QueryForge 部署运维手册

> 版本：v1.5（2026-10） · 读者：运维、部署实施
> 面向内网单机部署场景（Windows/Linux，venv + uvicorn，无 Docker）。

---

## 1. 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10+ / Linux |
| Python | >= 3.9, < 3.12（推荐 3.10.x） |
| 内存 | >= 8GB（BGE-M3 模型约 2.2GB，推理时额外占用） |
| 磁盘 | >= 10GB（模型 2.2GB + 向量索引 + 日志） |
| 网络 | 可访问大模型 API 地址（外部）；首次部署需访问 ModelScope 下载模型 |

---

## 2. 安装部署

### 2.1 获取代码并创建虚拟环境

```bash
cd QueryForge
python -m venv .venv
# Windows
.venv\Scripts\python.exe -m pip install -r requirements.txt
# Linux
.venv/bin/python -m pip install -r requirements.txt
```

> 必须使用项目自带 venv：系统 Python 可能缺 slowapi 等依赖，SQLAlchemy 版本也可能不兼容。

### 2.2 下载向量模型（可选但建议）

```bash
.venv\Scripts\python.exe download_model.py
```

模型（BAAI/bge-m3，约 2.2GB）从 ModelScope 下载到 `models/embeddings/bge-m3/`。下载失败时系统自动降级为数据库关键词检索，功能可用但召回质量下降。

### 2.3 初始化与启动

首次启动自动完成：建表（三库）→ 轻量迁移 → 种子数据（系统配置 + 默认管理员 + 默认角色）。

```bash
# Windows
start_server.bat

# 或直接运行
.venv\Scripts\python.exe main.py
```

启动后访问 `http://localhost:8888`。

**默认管理员：`admin` / `REDACTED`** —— 登录后立即修改密码；生产环境建议在系统设置关闭注册（`ALLOW_REGISTER=false`），由管理员建号。

### 2.4 启动自检（冒烟测试）

```bash
curl http://localhost:8888/api/system/site-branding          # 公开接口，应返回 200
# 登录后在浏览器开发者工具执行：
# GET /api/user/list   → 200 且返回用户列表
# GET /api/driver/list → 200
```

## 3. 配置说明

### 3.1 运行配置（`app/config.py`，改后重启生效）

| 配置 | 默认 | 说明 |
|---|---|---|
| `DATABASE_URL` | `''`（SQLite） | 留空 = SQLite；MySQL：`mysql+pymysql://user:pass@host:3306/queryforge?charset=utf8mb4`；PG：`postgresql+psycopg2://user:pass@host:5432/queryforge` |
| `TELEMETRY_DATABASE_URL` | `''` | 遥测库连接串；留空时 SQLite 用独立文件，外部库模式与主库同址 |
| `LOGS_DATABASE_URL` | `''` | 日志库连接串，规则同上 |
| `HOST` / `PORT` | `0.0.0.0` / `8888` | 监听地址与端口 |
| `DEBUG` | `False` | True 时开启 reload 与详细错误信息（仅开发用） |
| `SECRET_KEY` | `''` | JWT 签名密钥；**留空则首次初始化自动生成并持久化到 system_settings**；如手动设置请用强随机值 |
| `FERNET_KEY` | `''` | 留空时从 SECRET_KEY 派生（改动会导致已加密的密钥/密码无法解密，勿轻改） |
| `COOKIE_SECURE` | `False` | 启用 HTTPS 后置 True |
| `CORS_ORIGINS` | `[]` | 空 = 同源部署；跨域才填 |
| `FRAME_ANCESTORS` | `['self']` | CSP frame-ancestors；需被外部门户嵌入时填白名单 |
| `DB_POOL_SIZE` 等 | 10/20/30/3600 | 连接池参数 |
| `SLOW_REQUEST_MS` / `SLOW_SQL_MS` | 1000 / 500 | 慢接口/慢 SQL 告警阈值 |

> **密钥缺失拒绝启动**：SECRET_KEY 在 config 与 system_settings 都为空时服务拒绝启动——这是有意的安全设计，不存在硬编码兜底。

### 3.2 系统设置（管理后台「系统设置」，实时生效无需重启）

JWT 有效期（分钟，默认 4320）、注册开关、向量索引参数（`VECTOR_INDEX_THRESHOLD`=50 / `FIELD_RECALL_TOP_K`=20 / `MAX_TABLES`=10）、站点品牌（Logo/站点名）。运行期数据库优先，未设置时回落到 config 初始值。

### 3.3 切换 MySQL/PostgreSQL

1. 安装对应驱动（pymysql / psycopg2-binary，requirements 已含）；
2. 建空库（如 `CREATE DATABASE queryforge CHARACTER SET utf8mb4;`）；
3. 改 `app/config.py` 的 `DATABASE_URL`，重启；
4. 遥测/日志库默认与主库同址（ORM Base 隔离），需要独立库时填 `TELEMETRY_DATABASE_URL` / `LOGS_DATABASE_URL`；
5. 存量 SQLite 数据迁移不在自动范围内，需自行导出导入（结构可用 `deploy/*.sql` 对齐）。

## 4. 数据库与文件布局

```
QueryForge/
├── db/
│   ├── queryforge.db      # 主库（业务+元数据，外键开启）
│   ├── llm_telemetry.db   # 遥测库（LLM 调用）
│   ├── logs.db            # 日志库（查询审计/同步历史）
│   └── vectors/           # 向量索引 pickle（每库一个 _fields.pkl）
├── models/embeddings/bge-m3/   # 向量模型（约 2.2GB）
├── logs/                        # app/llm/audit/server 四类日志
└── deploy/                      # schema_main/telemetry/logs.sql + MIGRATIONS.md
```

- 三库均 WAL 模式；`*-wal` / `*-shm` 为正常伴随文件，**勿在服务运行期直接拷贝 db 文件做备份**（见 §6.2）；
- 表结构以 ORM `create_all` 为准；`deploy/*.sql` 由 `scripts/gen_schema_sql.py` 生成，CI 校验防漂移；存量库升级走 `db/sqlite_hooks.py` 幂等迁移（清单见 `deploy/MIGRATIONS.md`）。

## 5. 定时任务（内置，无需配置）

| 作业 | 时间 | 职责 |
|---|---|---|
| aggregate_usage | 每小时 | LLM 用量聚合（回溯 7 天幂等覆盖） |
| cleanup_telemetry | 03:00 | 遥测库清理（90 天） |
| cleanup_logs_db | 03:10 | 审计/同步历史清理（90 天） |
| cleanup_main_db | 03:30 | 对话结果 JSON 清理（30 天） |
| wal_checkpoint | 04:00 | 三库 WAL checkpoint（TRUNCATE） |
| run_scheduled_syncs | 每 10 分钟 | 派发到期的用户登记同步任务 |

管理后台「调度管理」可查看状态、手动触发、暂停/恢复。

## 6. 日常运维

### 6.1 日志

| 文件 | 内容 | 轮转 |
|---|---|---|
| `logs/app.log` | 业务/异常/慢接口 | 10MB × 5 份 |
| `logs/llm.log` | 模型调用请求/响应/Token | 10MB × 5 份 |
| `logs/audit.log` | 写操作/权限变更审计 | 10MB × 5 份 |
| `logs/server.log` | uvicorn 访问日志 | 按天 × 30 份 |

排查入口：先看 `app.log` 的 `[SLOW]` / `[SLOW SQL]` WARNING；查询链路问题查审计页「链路追踪」，比翻日志更直接。

### 6.2 备份

- **备份内容**：`db/*.db`（三库）+ `models/embeddings/bge-m3/`（模型可重新下载，可不备）+ `app/config.py`；
- **备份方式**：停服后复制；或用 SQLite 在线备份 API（`sqlite3 .backup` / VACUUM INTO），**运行期直接 cp db 文件会得到不一致快照**（WAL 模式）；
- **恢复**：停服 → 替换 db 文件 → 启动（schema 迁移幂等，不会重复执行）。

### 6.3 WAL 维护

每日 04:00 自动 `wal_checkpoint(TRUNCATE)`。如发现 `-wal` 文件异常增大（长事务/备份工具占用），确认无长事务后可手动执行：

```bash
sqlite3 db/queryforge.db "PRAGMA wal_checkpoint(TRUNCATE);"
```

### 6.4 升级流程

1. 停服 → 备份 db 与 config；
2. 更新代码（`git pull`，**勿在服务运行期执行 checkout/merge/reset**）；
3. `pip install -r requirements.txt`（如有依赖变化）；
4. 启动：轻量迁移自动执行（幂等），观察 `app.log` 无异常后放流量；
5. 如涉及表结构变更：ORM 改 `models/` → `python scripts/gen_schema_sql.py` 重新生成 DDL → 在 `deploy/MIGRATIONS.md` 登记。

### 6.5 密码与账号应急

- 忘记 admin 密码：停服执行 `.venv\Scripts\python.exe scripts/reset_admin_password.py`，按提示重置后启动；
- SECRET_KEY 丢失（误删 system_settings 行）：所有已签发 token 失效，用户重新登录即可；已加密的 API Key/数据源密码将无法解密，需重新配置。

## 7. 故障排查速查

| 现象 | 排查路径 |
|---|---|
| 服务起不来 | `app.log` 看堆栈；常见：端口被占、SECRET_KEY 缺失、依赖未装全 |
| 登录 401/无限跳登录 | token 过期（默认 3 天）或密码改过（旧 token 全部失效）；清 cookie 重登 |
| 提问报"未配置 API 密钥" | 模型管理页配置并测试连通性；注意 API 地址不能是内网 IP（SSRF 防护） |
| 生成 SQL 很慢 | `llm.log` 看模型耗时；模型配置把 timeout 调小；`app.log` 看是否 `[SLOW]` |
| 召回不准/漏表 | 字段描述是否完善；向量索引是否 stale（索引页重建）；调 Top_K/MAX_TABLES |
| 查询被拦截 | 审计页看该条链路追踪的 STEP7_GATEWAY：表级白名单外 or 字段 NONE/FILTER 误用 |
| 同步的库"删了又回来" | 先停用/删除对应同步任务再删库（调度器 10 分钟巡检） |
| 越权访问管理页 403 | 角色未授权该页面；权限管理页按 page 资源类型授权 |
| 外部库查询失败 | 数据源连接测试；数据源密码改过后引擎指纹变化会自动重建，仍失败则看密码是否正确 |
| db 文件巨大 | WAL 未 checkpoint（看 §6.3）；对话结果 JSON 30 天清理是否正常运行 |

## 8. 安全加固清单（生产必做）

- [ ] 修改默认管理员密码；
- [ ] 关闭注册（系统设置 → ALLOW_REGISTER = false），账号由管理员创建；
- [ ] 配置强 SECRET_KEY（或接受首次自动生成后备份 system_settings）；
- [ ] HTTPS 反代 + `COOKIE_SECURE=true` + `FRAME_ANCESTORS` 按需收敛；
- [ ] 大模型 API 使用专用密钥并定期轮换（Fernet 加密存储，接口不回显）；
- [ ] 按最小必要原则授权：数据源总闸 → 库 → 表 → 字段，敏感字段默认 FILTER/机密 NONE；
- [ ] 定期查看审计日志拦截记录与链路追踪；
- [ ] 服务器防火墙仅放行必要端口（默认 8888）；
- [ ] `db/`、`logs/`、`.venv/` 已列入 .gitignore，勿提交。
